# Meteo Dynamics

**Track how weather forecasts change.** Мобильный Frontend-only сервис, который показывает **не погоду, а поведение прогноза**: как
менялся прогноз на каждый конкретный час по мере выхода новых обновлений модели.

Обычное погодное приложение отвечает на вопрос «сколько градусов будет в 12:00». Здесь ответ
другой и для спортсменов с агрономами более важный: **насколько этому числу можно верить сейчас**.
Если неделю назад модель обещала 0 мм осадков, потом 2.9 мм, а сегодня снова 0 — прогноз ещё
не устоялся, и планировать работы рано.

## Быстрый запуск

Сборки нет: ни npm, ни бандлера, ни бэкенда. Три файла и браузер.

**Live Server в VS Code — рекомендуется**

1. Установите расширение **Live Server** (Ritwick Dey).
2. Правый клик по `index.html` → **Open with Live Server**.

**Любой статический сервер**

```bash
python3 -m http.server 4173
```

Затем откройте `http://localhost:4173`.

**Двойной клик по `index.html`** тоже работает — Open-Meteo отдаёт `Access-Control-Allow-Origin: *`,
поэтому запросы с `file://` не блокируются. Но с оговоркой ниже.

> **Важно про автоопределение локации.** Браузеры дают доступ к геолокации только в защищённом
> контексте — `https://` или `localhost`. При открытии через `file://` автоопределение молча не
> сработает, и приложение останется на городе по умолчанию (Рига); выбрать свой город можно
> вручную. Чтобы автоопределение работало, запускайте через Live Server или локальный сервер.
>
> То же касается **добавления на главный экран**: событие `beforeinstallprompt` приходит только
> по `https`. На `localhost` и `file://` баннер покажет ручную инструкцию.

> **Если правки не видны после обновления страницы** — браузер держит `app.js` в кэше.
> Live Server обновляет сам; простой `http.server` заголовков кэширования не шлёт, поэтому
> перезагрузите с игнорированием кэша (**Ctrl/Cmd + Shift + R**).

## Как устроен интерфейс

```
(📍 Rīga ▾)      (EN) (↑) (⚙)      ← всё в «таблетках» = всё нажимается
по умолчанию
─────────────────────────────────
[Чт 30.07][Пт 31.07][Сб 01.08]…    ← полоса дат, листается вбок
[Темп.][Облачность][Осадки][Ветер] ← какие показатели показывать
─────────────────────────────────
 ⊞ Добавить на главный экран    ×  ← баннер, не более 5 раз
─────────────────────────────────
            🌡️      ☁️      💧      💨
 12:00   19,6°↘  22%↗   0,0→   0,7↘   ← минимум
         24,5°   100%   1,5    3,9    ← максимум
─────────────────────────────────
 13:00   …тап раскрывает графики…
```

В шапке слева локация, справа три кнопки: **EN** (появляется, когда язык не английский),
**поделиться** и **шестерёнка** с настройками.

Всё нажимаемое оформлено одинаково — скруглённой «таблеткой» с рамкой: локация, EN, язык,
тема, даты, показатели. Пояснение внизу страницы, наоборот, лежит прямо на фоне без подложки,
чтобы его не приняли за кнопку.

### Два числа и стрелка

В каждой ячейке — **не одно значение, а разброс между всеми обновлениями модели** на этот час:

* **верхнее число** — минимум среди обновлений;
* **нижнее число** — максимум;
* **стрелка** — куда сместился прогноз от самого раннего обновления к актуальному
  (↗ вверх, ↘ вниз, → без изменений).

Оба числа набраны одинаково. Выделять одно из них нечем: минимум и максимум равноправны,
и жирное начертание на одном из них читалось бы как «это значение важнее», хотя это не так.

Широкий разброс = прогноз ещё «плавает». Узкий = модель уверена. Стрелка при этом может быть
плоской при широком разбросе — значит, прогноз качнулся в сторону и вернулся обратно.

### Раскрытие часа

Тап по строке раскрывает графики по каждому включённому показателю. По оси X — **дата выпуска
обновления**, слева самый ранний (7 дней назад), справа актуальный. Линия ступенчатая намеренно:
значение обновления держится ровно до выхода следующего.

Наведение курсора (или касание на телефоне) показывает подсказку сразу **по всем включённым
показателям** этого обновления — температура, облачность, осадки, ветер в одном месте.

### Терминология

Модель пересчитывает прогноз раз в сутки, и на один и тот же час существует несколько разных
ответов. Каждый такой ответ здесь называется **обновлением прогноза** — по-английски это
«model run», но в интерфейсе технический термин ни к чему. В подсказках всё сводится к самой
понятной форме: «Прогноз от 28.07».

### Показатели

Четыре колонки: температура, облачность, осадки, ветер — все включены по умолчанию. Любую можно
выключить кнопкой в панели показателей; отключить все сразу нельзя, минимум одна остаётся.
Четыре колонки помещаются даже на экране 375 px.

## Настройки, ссылка и установка

### Меню-шестерёнка

Язык, единицы и оформление лежат в одном месте — под шестерёнкой в шапке. Раньше единицы были
спрятаны внутри меню языков, и найти их было неочевидно.

Оформление получило три состояния вместо переключателя: **как в системе**, светлая, тёмная.
«Как в системе» — значение по умолчанию: страница следует настройке ОС, пока пользователь не
выберет своё.

### Поделиться

Кнопка со стрелкой рядом с шестерёнкой отдаёт ссылку на сервис. Порядок действий:

1. `navigator.share` — на телефоне открывается системное меню «Поделиться»;
2. если его нет — ссылка копируется в буфер обмена, появляется подтверждение;
3. если и буфер недоступен (нет разрешения) — ссылка показывается в сообщении, чтобы её можно
   было скопировать вручную.

### Добавить на главный экран

Приложение проверяет, не открыто ли оно уже как установленное
(`display-mode: standalone` или `navigator.standalone`) — тогда баннер не показывается совсем.

Если браузер поддерживает установку и присылает событие `beforeinstallprompt`, в баннере
появляется настоящая кнопка **«Добавить»**: нажатие открывает системный диалог установки.
Если такой возможности нет — например, в Safari на iOS её не существует — баннер показывает
инструкцию для конкретной платформы: «Поделиться → На экран „Домой“» или «меню браузера →
Установить приложение».

**Счётчик показов.** Баннер появляется не более **5 раз**, по одному на загрузку страницы, и
прямо в нём написано, какой это по счёту показ: «Напоминание 3 из 5 — потом исчезнет». После
пятого раза он больше не появляется. Крестик закрывает его навсегда сразу.

Манифест собирается в `injectManifest()` и подключается как `data:`-URL. Отдельный
`manifest.json` с иконками дал бы более надёжную установку, но нарушил бы условие «строго
четыре файла». Если браузер откажется читать такой манифест, установка просто пойдёт по ручной
инструкции — баннер работает в любом случае.

### Языки

Поддерживаются 16 языков: английский, русский, украинский, немецкий, французский, испанский,
португальский, итальянский, польский, латышский, литовский, эстонский, турецкий, китайский,
японский и арабский (с полной поддержкой письма справа налево).

Как выбирается язык при первом открытии:

1. Сохранённый выбор пользователя, если он есть;
2. иначе — **язык страны, определённой по геолокации** (Латвия → латышский, Литва → литовский,
   Казахстан → русский и так далее);
3. иначе — язык браузера;
4. иначе — английский.

**Кнопка «EN» всегда на виду** рядом с переключателем языка — один тап, и интерфейс на
английском, даже если пользователь не понимает текущий язык и не может найти нужный пункт меню.
Кнопка скрывается сама, когда английский уже выбран.

Как только язык выбран вручную, он закрепляется: смена города больше его не перебивает.
До этого момента язык подстраивается под страну автоматически.

Названия дней недели и разделитель дробной части берутся из `Intl` по выбранному языку — в
английском это «Sat» и `18.4`, в русском «сб» и `18,4`. Отдельного перевода они не требуют.

### Единицы

| Величина | Варианты |
|---|---|
| Температура | °C · °F |
| Ветер | км/ч · м/с · миль/ч · узлы |
| Осадки | мм · дюймы |

Единицы тоже подставляются по стране: США — °F, мили/ч, дюймы; Великобритания — °C, но мили/ч;
Россия, Балтия, Скандинавия, Китай, Япония — м/с для ветра; остальные — км/ч. Выбранное вручную
закрепляется и переживает смену локации.

Пересчёт идёт **на клиенте**: API всегда запрашивается в °C, км/ч и мм, а перевод в другие
единицы — обычная арифметика над уже загруженными данными. Поэтому переключение мгновенное и не
стоит ни одного сетевого запроса. Точность при этом не выдумывается: дюймы показываются с двумя
знаками, всё остальное — с одним.

### Что сохраняется на устройстве

Всё через `localStorage`, ключи `wf-*`:

| Ключ | Что хранит |
|---|---|
| `wf-lang` | выбранный язык (только при ручном выборе) |
| `wf-units` | единицы (только при ручном выборе) |
| `wf-theme` | `auto`, `light` или `dark` |
| `wf-place` | последняя локация |
| `wf-install-shows` | сколько раз показан баннер установки (до 5) |
| `wf-install-off` | баннер закрыт крестиком — больше не показывать |
| `wf-installed` | приложение уже добавлено на главный экран |

Проверено: после перезагрузки страницы все настройки восстанавливаются и не сбрасываются.
Счётчик баннера проверен по шагам — на пятой загрузке показывается «5 из 5», на шестой баннер
уже скрыт и счётчик не растёт.

## Выбор локации

1. **Автоопределение при первом запуске.** Приложение молча запрашивает геолокацию браузера,
   переводит координаты в название города через обратное геокодирование и подставляет результат.
   Если доступ отклонён или контекст незащищённый — молча остаётся город по умолчанию, без
   назойливых сообщений.
2. **Скорректировать вручную.** Тап по названию города открывает панель: кнопка повторного
   определения, поиск по названию и быстрые пресеты.
3. **Выбор запоминается** в `localStorage` и подставляется при следующем открытии — повторный
   запрос геолокации не делается.

Что и куда уходит: координаты отправляются в Open-Meteo (за погодой) и в BigDataCloud (за
названием города). Оба запроса идут напрямую из браузера, своего сервера у приложения нет, ничего
не логируется.

## Как устроены данные

### Источник

[Open-Meteo **Previous Model Runs API**](https://open-meteo.com/en/docs/previous-runs-api):

```
https://previous-runs-api.open-meteo.com/v1/forecast
```

Ключевая возможность — переменные вида `temperature_2m_previous_day3`: значение на **тот же самый
час**, но из обновления, выпущенного 3 дня назад.

Плюс два вспомогательных сервиса без ключей: [geocoding-api.open-meteo.com](https://open-meteo.com/en/docs/geocoding-api)
для поиска города по названию и [BigDataCloud](https://www.bigdatacloud.com/) для обратного
геокодирования.

### Один запрос на всё

При смене локации делается **ровно один** запрос: 4 показателя × 8 обновлений × 10 суток × 24 часа.
Это около **40 КБ** — после загрузки переключение дат и раскрытие часов идёт мгновенно, из памяти,
без обращений к сети (замерено: смена даты ≈ 140 мс).

### Откуда берутся числа и как их проверить

Всё, что показывает приложение, приходит одним GET-запросом. Вот он целиком для Риги — можно
вставить в адресную строку браузера и увидеть сырой JSON:

```
https://previous-runs-api.open-meteo.com/v1/forecast?latitude=56.9460&longitude=24.1059&hourly=temperature_2m,temperature_2m_previous_day1,temperature_2m_previous_day3,wind_speed_10m,wind_speed_10m_previous_day3&timezone=auto&past_days=2&forecast_days=8&wind_speed_unit=kmh
```

Как сверить: найдите в массиве `hourly.time` нужную метку (например `2026-08-01T09:00`),
запомните её порядковый номер и возьмите значение с тем же номером из `hourly.temperature_2m` —
это обновление «Сейчас». Значения из `..._previous_day1…7` — те же часы, но из обновлений, выпущенных
1–7 дней назад. Минимум и максимум этих восьми чисел приложение и показывает в строке часа.

#### Две оси времени — их легко перепутать

В данных два независимых измерения времени, и шаг у них разный:

| | **На какой час прогноз** (valid time) | **Когда прогноз выпущен** (run time) |
|---|---|---|
| Шаг | **1 час** | **24 часа** |
| Сколько точек | 240 (10 суток) | 8 (актуальный + 7 предыдущих) |
| Откуда | элементы массива `hourly.time` | переменные `previous_day1…7` |
| Где видно в интерфейсе | строки списка часов | точки на графике внутри раскрытой строки |

**Часовое разрешение нигде не теряется:** каждый час суток — отдельная строка, группировки по
дням нет. По дням идёт только вторая ось — глубина архива.

И это ограничение самого API, а не округление в приложении: имена `previous_hour1` и
`previous_run1` эндпоинт отклоняет с ошибкой, принимается только `previous_dayN`; `previous_day8`
имя принимает, но возвращает пустые значения. Модели физически считаются 2–4 раза в сутки, то
есть между соседними суточными срезами были промежуточные обновления — через этот эндпоинт они
недоступны.

#### Остальные параметры

| Параметр | Значение | Чем подтверждается |
|---|---|---|
| Модель | `best_match` — Open-Meteo сам выбирает лучшую для точки | для Риги совпадает с `metno_seamless`, для других мест будет другая |
| Точность температуры | 0,1 °C | максимум знаков в ответе |
| Точность ветра | 0,1 км/ч | то же |
| Точность осадков | 0,1 мм | то же |
| Точность облачности | целые проценты | в ответе только целые |

Приложение нигде не добавляет знаков сверх того, что дал API: облачность выводится целыми,
осадки — с одним знаком. Никаких сглаживаний, интерполяций и досчётов нет — только выбор
минимума, максимума и разности между крайними обновлениями.

### Насколько этим числам можно верить

Три оговорки, которые стоит держать в голове.

**Это расчёт модели, а не измерения.** Метеостанции здесь не участвуют. Прогноз на прошедшие
часы — тоже прогноз, а не факт; сравнить его с реальностью через это приложение нельзя.

**Разные модели расходятся не меньше, чем разные обновления.** Для Риги на один и тот же час
01.08 12:00 модели дали: ICON-EU 20,3 °C, UKMO 22,0 °C, KNMI HARMONIE 22,6 °C,
DMI HARMONIE 22,8 °C, ECMWF IFS 21,4 °C, MET Norway 23,6 °C. Разброс 3,3 °C — сопоставим с тем,
что приложение измеряет между обновлениями. То есть выбор модели влияет на результат примерно так же
сильно, как и обновление прогноза.

Приложение использует `best_match` (выбор Open-Meteo по умолчанию). Какая именно модель за ним
стоит, в ответе API не указано — определить можно только сравнением с явными моделями. Если нужна
фиксированная модель, добавьте в запрос `&models=ecmwf_ifs025` (или другую) в `buildUrl()`
внутри `app.js`.

**Значение относится к ячейке сетки, а не к точке.** Архивный API отвечает на 0,25° сетке: для
запроса 56.946, 24.106 возвращается ячейка 57.00, 24.00 — это примерно 6 км в сторону. В поле
`elevation` видно высоту, к которой привязан расчёт; если она сильно расходится с реальной
высотой вашей точки, температура будет смещена. Для горного рельефа расхождение заметнее всего.

### Ограничение архива

**Реальные архивные обновления доступны за 1–7 дней.** Глубже Open-Meteo предыдущие обновления не
хранит, поэтому глубина 8 обновлений (актуальный + 7) — это потолок источника, а не приложения.

### Защита от ложной уверенности

Есть неочевидный подвох. Когда старый обновление физически не мог покрыть целевой час (событие
далеко в будущем, а обновление недельной давности до него не дотягивался), API возвращает не `null`,
а **значения текущего обновления**. Наивная реализация сравнила бы прогноз сам с собой, увидела
нулевой разброс и показала бы идеальную стабильность там, где сравнивать не с чем.

Приложение это отлавливает: если все обновления совпали до последнего знака по всем показателям, при
раскрытии часа выводится прямое предупреждение вместо ложного «всё стабильно». Четыре независимых
обновления практически никогда не совпадают до 0,1 °C одновременно по температуре, облачности,
осадкам и ветру, так что ложных срабатываний на реальных данных нет.

Практический вывод: **для даты дальше ~7–10 дней динамику смотреть рано** — вернитесь через
несколько дней, когда накопятся независимые обновления.

## Оформление и доступность

* Мобильный интерфейс в первую очередь; от 660 px раскладка центрируется, шире не растягивается.
* Светлая и тёмная темы, переключатель запоминает выбор; по умолчанию берётся системная настройка.
* Цвета линий (оранжевый / синий / зелёный / фиолетовый) проверены на различимость при
  дальтонизме и на контраст к фону в обеих темах.
* Цвет нигде не единственный носитель смысла: у каждого графика подпись, у стрелок — форма
  глифа, а не только окраска.
* Липкие шапка и полоса дат, безопасные зоны `env(safe-area-inset-*)` под вырезы экрана.
* Размер поля поиска 15 px — iOS не зумит страницу при фокусе.
* Учитывается `prefers-reduced-motion`, есть стили для печати и `forced-colors`.
* Горизонтальной прокрутки страницы нет ни на одной ширине; полосы дат и показателей скроллятся
  внутри себя. Проверено и для письма справа налево: арабский не растягивает документ вбок.
* В арабском выставляется `dir="rtl"`, интерфейс зеркалится целиком. Графики остаются слева
  направо — ось времени так читается во всех языках.

## Известные ограничения

* Архив обновлений — 7 суток (ограничение источника).
* Языков 16, а не «все». Каждый добавленный язык — это ещё один объект на 47 строк в `T`
  внутри `app.js` плюс запись в `LANG_NAMES`; механизм готов, но машинный перевод на сотню
  языков без вычитки дал бы текст, за качество которого нельзя ручаться. Названия городов
  при этом приходят на выбранном языке из геокодера Open-Meteo и переводить их не нужно.
* Прогноз берётся из мультимодельного `best_match` Open-Meteo; выбора конкретной модели
  (ICON, GFS, ECMWF) нет.
* Данные не кешируются между перезагрузками — каждое открытие делает свежий запрос.
* Обратное геокодирование зависит от стороннего сервиса; при его недоступности локация
  показывается координатами, погода при этом работает нормально.
